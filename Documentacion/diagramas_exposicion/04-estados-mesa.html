State machine · reglas del salón

Una mesa solo cambia por transiciones permitidas

El estado actual de la mesa gobierna qué acciones se aceptan. Las etiquetas del recorrido corresponden a los eventos que expone `MesaService` y el estado resaltado es el que recibe pedidos cuando la mesa queda ocupada.

Evidencia · máquina de estados

El `switch` formaliza el contrato

Backend/.../service/MesaService.java · líneas 129–141 
private boolean esTransicionPermitida(
        EstadoMesa actual, EstadoMesa nuevo) {
    if (actual == nuevo) return true;

    return switch (actual) {
        case LIBRE -> nuevo == EstadoMesa.OCUPADA
                || nuevo == EstadoMesa.RESERVADA
                || nuevo == EstadoMesa.FUERA_DE_SERVICIO;
        case RESERVADA -> nuevo == EstadoMesa.OCUPADA
                || nuevo == EstadoMesa.LIBRE;
        case OCUPADA -> nuevo == EstadoMesa.LIBRE;
        case FUERA_DE_SERVICIO -> nuevo == EstadoMesa.LIBRE;
    };
}

Evidencia · acciones

Las operaciones llaman al mismo DAO

Backend/.../service/MesaService.java · líneas 59–107 
public String ocupar(int mesaId) {
    Mesa mesa = mesaDAO.getMesaPorId(mesaId);
    if (!ESTADOS_OCUPABLES.contains(mesa.getEstado())) {
        return "La mesa no puede ocuparse";
    }
    return mesaDAO.cambiarEstado(mesaId, EstadoMesa.OCUPADA);
}

public String liberar(int mesaId) {
    // cierra pedidos activos de la mesa
    return mesaDAO.cambiarEstado(mesaId, EstadoMesa.LIBRE);
}

Qué decir

“El estado evita que la interfaz invente reglas”

Los botones de la vista pueden ocultarse o mostrarse según el estado, pero la decisión definitiva vive en `MesaService`. Por eso una reserva no se puede crear sobre una mesa ocupada y una mesa fuera de servicio solo vuelve a estar libre mediante una transición válida.
